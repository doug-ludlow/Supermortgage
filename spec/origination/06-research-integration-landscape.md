# 00b-orig — Integration Landscape: Fannie Mae Origination Technology and Origination Counterparties

**Purpose.** Inventory every external system and counterparty the Supermortgage origination platform (own LOS core, TypeScript/Postgres) must integrate with for Fannie Mae conventional conforming first liens sold whole-loan for cash with servicing retained by the partner. For each: purpose in the lifecycle, the machine interface *actually documented* (API / B2B file / portal-only / vendor-specific), auth and onboarding, data format/standard, timing, owner (partner as Fannie Mae seller vs Supermortgage as TSP/operator), and a confidence flag.

**Research date.** All web sources were retrieved and read on **2026-09-10** unless noted. Confidence flags: **VERIFIED** (read on a primary page/document that states it), **PARTIALLY VERIFIED** (primary source confirms existence but not the specific mechanics, or a vendor/press source only), **UNVERIFIED** (not confirmed from any source read; do not cite as fact in a spec). Writers cite entries as "00b-orig F6" / "00b-orig N9".

**Companion document.** The servicing-side landscape (`claude/03-research-integration-landscape.md`, "00b", verified 2026-09-09) is referenced as **00b-svc** and is *not* re-verified here. In particular 00b-svc F14 (Developer Portal auth: OAuth 2.0 ROPC at `fmsso-api.fanniemae.com/as/token.oauth2`, headers `x-fnma-api-key` / `x-fnma-access-token`, integration env `api-clve.fanniemae.com`, production `api.fanniemae.com`; TLS/cipher cutover Oct 23, 2026), 00b-svc Part B(a) (Technology Manager roles, System IDs, Form 101/TR101 Data Access Authorization Agreement, TSP Intake Form → Integration Agreement → 2–6 months), 00b-svc N1 (MERS membership categories and pricing), N5 (flood), N8 (document custodian RDC v15, Form 2017/2008/2009/2004A), N9 (print/mail), N10 (Nacha), N15 (eRecording) apply unchanged.

**Operating model assumed** (inventory §"Operating model"): partner = lender of record and Fannie Mae seller/servicer; Supermortgage (SM) = fulfillment/technology layer (Fannie Mae TSP), warehouse provider, and subservicer. Every Fannie Mae submission is made under the partner's 9-digit seller/servicer number through partner-scoped credentials (Form 101 / "TSP Product" System IDs in the partner's Technology Manager org) and/or SM's own TSP identity.

## Part A — Fannie Mae origination technology

### F12 first: the two integration rails and how a TSP gets in

Because every F-entry depends on it, the credential/rail model is documented first.

**Rail 1 — Developer Portal REST APIs (JSON).** The Developer Portal page (verified 2026-09-10) lists Business Partner APIs by group. Origination-relevant products:
- *Originating & Underwriting*: **AMI Lookup and HomeReady® Evaluation** ("Speed up pre-qualification and reduce manual steps. Identify HomeReady-eligible borrowers earlier"); **Appraisal File Retrieval** ("Get access to the full appraisal data in an easily consumable file format (XML)"); **Appraisal Findings Summary** ("Get appraisal summary status, findings, messages, and Collateral Underwriter® (CU®) risk score"); **Loan Lookup** ("Determine in real time if a loan is owned by Fannie Mae for the purpose of identifying eligibility"); **Property Data** ("Unlock the benefits of our value acceptance + property data offering and ensure compliance").
- *Pricing & Execution*: **Loan Pricing and Committing** ("Improve price transparency, make your Best Efforts execution decisions, and commit loans"); **Mission Score**; **Servicing Released Premium Pricing**; **Servicing Released Premium Pricing Calculator** ("Automate the rate sheet upload process").
- *Insights & Reporting*: **Buy Up Buy Down Daily** ("loan-level details from the previous day's closed MBS pools" — **MBS only; not applicable to whole-loan cash execution**); **Committing and Delivery Fee Draft Notifications** ("Retrieve all adjustments made at the loan, commitment, and lender levels"); **Loan-Level Draft Notifications**; **Whole Loan Purchase Advice Sellers** and **Whole Loan Purchase Advice Servicers** ("Retrieve loan-level financial details about the whole loan purchase").
- There is **no DU, DO, EarlyCheck, UCD, Loan Delivery, CPM, or "DU Messages" API product** in the catalog. Auth for Rail 1 is the OAuth 2.0 ROPC pattern in 00b-svc F14 (System ID + Client ID/Secret; `x-fnma-api-key`, `x-fnma-access-token`; `api-clve` integration env).

**Rail 2 — "Direct Integration" (DI) B2B XML platform.** Four origination systems document a system-to-system channel that predates the Developer Portal:
- DU/DO: the "DU Specification" (MISMO v3.4) with a "DU Integration environment" (DU/DO Integration Impact Memo, Apr 21, 2025: "This update will be available in the DU Integration environment on or about May 21, 2025"; the memo describes the "DO GetLenders XML response" / `DO_GET_LENDERS_RESPONSE`, i.e., XML request/response messages).
- EarlyCheck: "Direct Integration with a lender's loan origination system (LOS) and/or delivery/secondary system" ("a DU-like integration solution"). The Technology Integration Resources page lists an "XIS DNS/IP Address Update Integration Impact Memo | Sept. 17, 2025" under EarlyCheck — the DI gateway hostnames/IPs are subject to change notices [PARTIALLY VERIFIED that "XIS" is the gateway name].
- UCDP: "Integrated B2B Solution — Vendor-provided solutions that offer an integrated system interface, or direct integration (DI), to UCDP" (UCDP Overview, updated Sept 2025); "UCDP Technical Integration Guide for UAD 3.6" listed.
- UCD Collection Solution: "Direct Integration (DI): Our business-to-business integration platform enables UCD file submission directly from a lender's system and generates feedback messages"; "UCD v2.0 Readiness Checklist – Direct Integrators".
- **Transport/auth for Rail 2 is not on public pages** (the DU Implementation Guide v2.6.1 defines only the XML payload). Plan for a SOAP/HTTPS-style XML envelope with System-ID credentials and confirm in the Integration Agreement phase [PARTIALLY VERIFIED].

**Who may connect.** TSP page: "For lenders looking to directly integrate with Fannie Mae technologies, connect with your Fannie Mae account team to learn more about how to get started"; "The latest resources, test cases, release notes, and integration impact memos can be found on the Technology Integration page." The TSP path (Intake Form → Integration Agreement → Strategic Alliances Manager → integration environment → production, "two (2) to six (6) months") is in 00b-svc Part B(a). Lender-side authorization of a TSP is done in Technology Manager: the job aid "Lender CA – Add API System ID to a TSP Product" walks a lender Corporate Administrator through *Manage TSP Product → Available Product → Set Up Product → +Add User/System IDs → +Add Applications → roles/data folders → Complete Set Up "to assign Product to the API System ID"*; a companion job aid covers "Revoke API System ID Access to TSP Product". IP Address Restrictions are "an optional feature, which, when enabled, will block access to Fannie Mae technology if the request was not initiated from specified and registered IP address ranges"; "Administrators may enable IP Address Restrictions for either User IDs, System IDs, or both"; and "If your users or systems access Fannie Mae applications through a Technology Service Provider's (TSP) solution (e.g., an LOS), you will also need to provide a list of allowable IP address ranges that will apply to the TSP's system(s) in Technology Manager." Form 101 (Data Access Authorization Agreement) governs SM's access to the partner's data (00b-svc).

**Design implication.** Same dual-credential model as servicing: SM's own TSP org/System IDs for the integration, plus partner-org System IDs assigned to SM's "TSP Product" so DU casefiles, UCDP submissions, UCD files, EarlyCheck runs, commitments and deliveries are attributed to the partner's seller number. Register SM egress IP ranges in the partner's TM org if the partner enables IP restrictions.

### F2. UCDP and Collateral Underwriter
- **What/when.** "A single portal for the submission of appraisal report data files to Fannie Mae and Freddie Mac"; "Appraisal reports for all conventional mortgages delivered to the GSEs must be submitted to UCDP before the delivery date of the mortgage" (UCDP Overview, Sept 2025). "All appraisal reports successfully uploaded to UCDP receive an SSR for each GSE submission … status of the submission(s), and a Document File Identifier (Doc File ID)"; "One Doc File ID is assigned per loan and is the same for delivery to either GSE. Lenders are required to deliver a Doc File ID to each GSE's loan delivery system"; UCDP "does not allow a lender to reuse a Document File ID created from another lender's UCDP submission" (UAD 3.6 FAQ #5). CU feedback is "real-time feedback on submissions to Fannie Mae — including risk scores, flags, and messages powered by Collateral Underwriter® (CU®)"; for some UAD 2.6 submissions users may "request overrides when submissions are not accepted."
- **Channels.** UCDP UI; "Integrated B2B Solution … direct integration (DI)"; lender agents "must complete the UCDP registration process" (AMC/lender-agent registration form exists); Developer Portal **Appraisal File Retrieval** (XML) and **Appraisal Findings Summary** (CU risk score) APIs; **UAD Compliance API (UCA)** (fact sheet + six test cases: URAR / Appraisal Update / Completion Report, with and without findings) — this lets SM validate a UAD 3.6 file before UCDP submission. SSR resources: "SSR JSON Data Dictionary", "SSR JSON Schema v 1.0", "SSR Guide for UAD 3.6".
- **Formats/dates.** UAD 2.6: "MISMO 2.6 Errata 1 GSE Extended format" XML "with an embedded first-generation PDF"; UAD 3.6: "packaged in a Zip file and include: UAD 3.6 XML" plus PDF and an Images folder. **Broad production Jan 26, 2026; UAD 3.6 mandatory "for all new appraisal reports submitted to UCDP on or after November 2, 2026"; UAD 2.6 revisions allowed "through the retirement date on May 3, 2027."** Under UAD 3.6, "Restricted Appraisal Update Reports and Completion Reports are no longer one report. They will be two separate reports" and "must be submitted in UAD 3.6 ZIP format" (replaces the 1004D workflow). SSR messaging updates for UAD 3.6 announced June 4, 2026.
- **Onboarding.** "Each GSE has separate multi-step registration processes"; roles "lender administrator" and "Lender Agent administrator"; "If a lender delivers loans to both GSEs, the primary lender administrator must be the same for both GSEs"; account management in TM. Fees: none stated on the pages read [UNVERIFIED].
- **Owner.** Partner is the registered lender; SM (or the AMC) acts as lender agent; Doc File ID and SSR stored on `appraisals`.

## Part (c) — Interface-type findings that most affect architecture
1. **Two Fannie Mae rails, one credential model.** DU/DO, EarlyCheck, UCDP and UCD run on the legacy Direct Integration XML platform (DU Spec MISMO 3.4 → EarlyCheck; UAD 3.6 ZIP → UCDP; UCD XML → UCD Collection; DU Findings JSON v2 back), while VA+PD, appraisal findings/retrieval, AMI/HomeReady, Loan Lookup, pricing/committing and purchase advice are Developer Portal REST/JSON APIs. Build `integrations/fnma-di` (signed XML over HTTPS, System-ID auth, integration-env routing, version pinning to "one version of current") and `integrations/fnma-api` (OAuth ROPC token cache, 5-minute TTL, `api-clve` vs production) as two adapters sharing the partner-scoped credential store. Register SM egress IPs in the partner's TM org.
2. **Loan Delivery is the un-automatable step.** With no API/DI, the delivery pipeline must end in a human-operated (or Fannie-permitted) UI action. Design `deliveries` so that the ULDD file, EarlyCheck results and DU/UCDP/UCD IDs are frozen and hashed before the operator imports; treat Loan Delivery's status (Draft → Purchase Requested → Purchase Ready → Purchased and Funded; certification Awaiting/Certified/Qualified Cert) as an externally observed state machine reconciled from the UI/Connect reports and the Purchase Advice API, not as a command result. Ask Fannie Mae's Integration Team explicitly whether a Loan Delivery DI channel exists for TSPs before finalizing 29.4.
3. **Identifiers are the glue.** DU Casefile ID, UCDP Doc File ID (one per loan, both GSEs, not reusable across lenders), UCD Casefile ID, Property Data ID, CPM Project/Certification IDs, Income Calculator `VerificationReportIdentifier`, DU validation report reference numbers, PE-WL quote ID/commitment number, Wire Instruction Reference Identifier (SID 398.3), MERS MIN and eNote Controller/Location/Secured Party — every one must be persisted on the canonical entities and delivered in ULDD; Loan Delivery edits with prefixes A/C/D fail when they do not match.
4. **Dated mandates drive rule-set versions.** UAD 3.6 mandatory Nov 2, 2026 (UAD 2.6 retired May 3, 2027); DU V.12.1 VantageScore update Sept 9, 2026 and DU V.12.1 Sept 25, 2026; UCD v2.0 mandate dates to be announced Q4 2026; MERS Procedures Rel. 26.1 (May 17, 2026); Fannie Mae TLS cipher cutover Oct 23, 2026; HMDA 2026 FIG. Feature flags `uad.3_6_required`, `fnma.du.<version>`, `fnma.ucd.<version>`, `mers.proc.26.1`.
5. **Verification data never transits SM to DU.** DU validation-service suppliers send report data to Fannie Mae directly; SM orders, stores the report reference and outcome, and cites it in the DU submission. The same "supplier-of-record" pattern applies to Income Calculator (TSP submits, DU matches by identifier) and PDC (vendor or SM submits to the Property Data API before the note date).
6. **eNote control plane is MERS, custody is Fannie Mae after purchase.** Registration ≤1 BD after tamper-seal, digitally signed XML from an eRegistry-integrated eVault, eDelivery to Fannie Mae's eVault, same-day-effective Transfer of Control and Location, Secured Party for the warehouse interest, Servicing Agent/Master Servicer fields for the subservicer. The `enotes`/`mers_transactions` tables and the shared eVault adapter (1.4) must support all six rights-holder roles and Change Status/Registration Reversal.
7. **Warehouse and secondary are entangled inside Fannie Mae's tools.** Bailee-letter validation is by letterhead text match; Form 2004A conditions release on proceeds delivery; purchase proceeds move on the 7:30 a.m. ET custodian rule and "next business day" wiring; the SM warehouse ledger must consume the Purchase Advice API (daily JSON) and the Committing & Delivery Fee Draft Notifications API for the same-day payoff and gain-on-sale postings.
8. **Public-sector APIs are real and free** (FFIEC HMDA Filing API with Login.gov/OIDC, Rate Spread API, OFAC SLS downloads, IRS IVES A2A, SSA CBSV Web Service, FinCEN SDTM) — build them in-house; only the counseling-list generation and APOR cadence need a confirmation pass.
9. **Vendor specs are contract-gated** (MI ordering, AMC APIs, title systems, fraud tools, credit resellers beyond Xactus, eClosing platforms). Keep the generic adapter layer from 00b-svc Part E(4) and standardize on MISMO 3.4/3.5 payloads (credit 2.x still common), with per-vendor codecs.
