**Discrepancies vs blueprint**
1. The blueprint cites "C2-1.2 (delivery requirements)"; delivery data requirements are **C1-2-02** (10/04/2023). C2-1.2 is the best-efforts commitment chapter (C2-1.2-02, 03/03/2021 — 29.1).
2. "E-1 (document custodian requirements)" is wrong: custodial documents are **E-2-01, Required Custodial Documents (05/04/2022)**, custodian arrangements are A3-3-04/A3-3-05 (05/04/2022), and the operating rules are the "Requirements for Document Custodians" Version 15.0 (August 2025) — all 29.4.
3. The Wire Instruction Reference Identifier (SID 398.3) named in the assignment (via 00b-orig Part (c)) is documented by Fannie Mae as an **MBS-pool** field ("standard MBS Pools only"); for whole-loan cash execution the wire is designated by a **payee code** (Form 482; ULDD Sort ID 642 "required for: Cash loans (Whole Loans)… if the loan is under Bailee Letter at time of delivery") plus the Warehouse Lender Identifier (Sort ID 650.1). Terminology trap for operators: Loan Delivery's Seller Profile Loan Detail tab displays Sort ID 642 (Payee Identifier) as "Wire Nickname" and Sort ID 650.1 as "Warehouse Lender" (ULDD FAQ Q6, re-read 2026-09-11) — the label overlaps with the MBS-only SID 398.3 "Wire Instruction Reference Identifier (Wire Nickname)", but the whole-loan value is the Form 482 payee code. 29.3 leaves SID 398.3 empty; 29.4 assigns the payee code.
4. The "UCD Casefile ID" is not a separate identifier: the UCD is keyed by the Fannie Mae Casefile ID, which is the DU casefile ID; UCD assigns one only when DU did not (FAQ Q4). The consistency rule is therefore `ucd_submissions.casefile_id_ucd = du_casefiles.casefile_id`.
5. The Property Data ID (Property Data API), the Income Calculator `VerificationReportIdentifier` and the DU validation report identifiers are DU-Spec / Property Data API identifiers matched by Fannie Mae through the casefile; no ULDD Phase 5 Sort ID for them was found on the pages read **[UNVERIFIED whether Appendix D carries any of them]** — they are persisted on the loan and asserted present, not (by default) written into the ULDD.
6. "ULDD Specification (current phase)" — the current document is Phase 5 (5.2.0) of May 26, 2026 with **no future mandate date** ("ULDD PHASE 5 Mandate Date: n/a"); the Phase 5.0 mandate took effect July 28, 2025. The rule set is `fnma.uldd.5.2.0`.
7. "Data must match closing documents and DU final submission" is enforced by Fannie Mae as Loan Delivery edits (A/C/D prefixes, DU Compare) and by C1-2-02's "clear of all fatal edits", UCD "Successful" and UCDP-before-delivery requirements — not by a single matching rule; the process implements each as a gate.
8. A clean EarlyCheck run is **not** a clean Loan Delivery import: EarlyCheck "does not include product eligibility edits…customer contract and commitment pricing edits, and pooling rules" (FAQ Q6), so 3000-series commitment edits are first seen in Loan Delivery (29.4).
9. The blueprint omits the SFC cap (ten per loan), SFC 067/VantageScore 4.0 data, SFC 861/920 for RON/RIN, SFC 508 for eNotes, and the SID 311 ↔ UCD 3.038 rate-lock date validation.
10. The blueprint lists "EarlyCheck user guide/API"; there is no Developer Portal API — EarlyCheck is a Direct Integration XML service plus a web UI (00b-orig F12/F4).

#### State machine

`deliveries.build_status` (owned here): `pending_prerequisites` → `assembling` (`loan.funded` and all upstream gate inputs present) → `du_file_checked` (EarlyCheck run on the final DU Spec file is clean — normally already done pre-closing by 23.1's final submission; re-used if the file hash is unchanged) → `uldd_built` (`delivery.uldd.built`; schema-valid XML) → `earlycheck_pending` → `earlycheck_clean` (zero fatal, zero warning-to-fatal; warnings each carry a recorded justification) | `earlycheck_failed` (→ `assembling` after correction; each fatal edit maps to an owning process which is notified) → `frozen` (`delivery.package.frozen`; hash stored) → hand-off to 29.4 (`delivery_packages.status = handed_to_operator`). Re-entry: `frozen` → `superseded` (any mapped source data changes, a post-funding corrected CD, a Loan Delivery fatal edit observed by 29.4, or a commitment change) → `assembling` with `uldd_build_no + 1`. Terminal for 29.3: `frozen` with `delivery_packages.status = imported` (29.4 sets) or `withdrawn` (loan repurchased by the partner/warehouse, rescinded, or not delivered — 29.1 pair-off rules). Guards: `uldd_built` requires the identifier-consistency gate and the SFC gate; `frozen` requires every composed gate in `gate_results` to be `open` at freeze time; `assembling` is refused while `loan_delivery_status ∈ {purchase_requested, purchase_ready, purchased_and_funded}` — post-submission corrections go through 29.4's data-revision or PPA paths, never through a silent rebuild.

#### Business rules and calculations

**R1 — Assembly from the closed-loan snapshot.** The ULDD is built from the same `closed_loan_snapshot` that 23.1's final DU submission hashed (`closed_loan_snapshot_hash`), overlaid with post-closing facts (disbursement date, funded UPB, escrow initial deposit, MIN, recording status, custodian FIN, payee code, commitment number). `deliveries.closed_loan_snapshot_hash` must equal `du_submissions.closed_loan_snapshot_hash` of the final submission, otherwise `FNMA_B3_2_10_DU_FINAL_MATCH_GATE` reopens (23.1) — this is the pre-emptive form of the "D" edits. The "At Current" Loan State date (FAQ Q37) is the build date; "At Closing" values are the CD-final figures.

**R2 — Sort-ID population and conditionality.** For every Appendix D row in `fnma.uldd.5.2.0`: `R` → must be populated or the build fails; `CR`/`CI` → the business condition is evaluated from the loan (`condition_evaluated = true`, result recorded) and populated when true; `O` (Freddie-only) → omitted. Format lengths are not enforced beyond the schema (FAQ Q36) except where Fannie Mae states a reasonable-value rule: SID 82 must be 10 characters (and begin with a digit ≥ 2 for a UAD 3.6 appraisal); SID 412 ≤ 10 characters with no added leading zeros; ULI ≤ 45 characters. Enumerations are validated against Appendix E; unknown enumerations fail the build rather than being coerced.

**R3 — Identifier consistency (`FNMA_ULDD_IDENTIFIER_CONSISTENCY_GATE`).** All of: (a) SID 322 = `du_casefiles.casefile_id` of the final submission (`du_submissions.is_final = true`, recommendation Approve/Eligible); (b) `ucd_submissions.casefile_id_ucd` = SID 322 and `ucd_submissions.status ∈ {accepted, accepted_with_warnings}` with `is_final = true` and `embedded_cd_disclosure_id` = the latest delivered CD; (c) SID 82 = `ucdp_submissions.doc_file_id` of the accepted final appraisal version with Fannie Mae status `successful` (blank only when SID 376 = `ValueAcceptance`); (d) SID 376 = `ValueAcceptance` ⇔ SFC 801/774 present ⇔ `valuation_orders.method ∈ {value_acceptance, value_acceptance_pd}`, and for `value_acceptance_pd` a `property_data_collections.property_data_id` exists with `submitted_at < note_date`; (e) SIDs 39/49.1/49.2 populated ⇔ `project_reviews.review_type = cpm` (Q24), unexpired at the note date (24.3 gate); (f) SID 412 = `mi_certificates.certificate_number` and coverage = `mi_certificates.coverage_pct` when `mi_certificates.status = active`; SID 429 = `NoMIBasedOnOriginalLTV` when base LTV ≤ 80% and no MI; SID 430.1 populated only for LPMI; SFC 019 ⇔ `premium_plan ∈ {lpmi_monthly, lpmi_single}`; SFC 281 ⇔ `financed_premium_cents > 0`; (g) SID 311 (PriceLockDatetime) = `ucd_submissions` CurrentRateSetDate (UID 3.038) = `locks.locked_at::date` of the lock in force at consummation, or the extension date only if the extension changed the rate (Q23); (h) SID 401 = `enotes.min` / `mers_transactions` MIN for a MOM loan; (i) SID 642 = the payee code approved for this loan (29.4 `wire_instructions.payee_code`) and SID 650.1 = SM's warehouse-lender identifier whenever `warehouse_advances.repaid_at is null`; (j) SIDs 620/652 = the custodian FIN in the partner's Seller Profile; (k) commitment number = `commitments.commitment_id_fnma` with `expires_on > today` and `type` consistent with `execution_type`; (l) `enote_indicator = (closings.closing_type ∈ {ron, ipen} ∧ enotes.registered_at is not null)` and SFC 508 ⇔ `enote_indicator`; (m) `ron_indicator`/SFC 861 ⇔ `signing_sessions.notarization_kind = ron` for the security instrument; SFC 920 ⇔ `rin`; (n) SFC 067 rule (separate gate); (o) SID 251 = the loan representative score computed by 22.2's rule ("Middle Or Lower Then Lowest", SID 249) and SID 251.1 = the model family of `applications.score_model`; (p) related-loan containers (≤ 3) for every `subordinations` row with SFC 118 when the subordinate lien is a Community Seconds (`LoanAffordableIndicator` SID 513.1 true), and SID 513.1 = false for a resubordinated lien whose Community Seconds status cannot be established on a refinance (Q10); (q) SID 363 EscrowBalanceAmount = `escrow_accounts` initial deposit (cents → dollars, two decimals) when escrowed.

**R4 — SFC assembly (`sfc_assignments`).** Start from 23.2's required set (127 always; 067; 900; 184; 801/774; 808; 118; 009/014; 168; 304; 007/003), add 24.4 (155/168/304), 24.5 (180 when no residential structure is in an SFHA and no flood policy is in place), 24.6 (019/281), 26.2 (508 eNote; 861 RON; 920 RIN), 22.3 (707), 24.3 (859/235/588), 20.4 pricing flags (874 DTS waiver when the pricing engine applied it), 31.1 (211/212 only if the partner's TPO analysis concludes the fulfillment arrangement is a correspondent/broker relationship — default none, open question Q3). Remove codes flagged `auto_derived_by_fnma` only if the Business Rules Dictionary lists them as derived; otherwise deliver them. If more than ten remain, escalate to `officer` (partner) with the Fannie Mae contact record rather than silently dropping a code.

**R5 — Computed delivery fields (EarlyCheck recomputes and compares).** LTV/CLTV/HCLTV use 23.1's rounding (per B2-1.2-01: ratio rounded to two decimals then compared to the eligibility ceiling — 23.1 owns the formula); DTI = 22.5's qualifying ratio; monthly income/debt as delivered to DU. Any EarlyCheck "calculation of key delivery fields" that differs from the platform's value by more than rounding tolerance (0.01 percentage point for ratios; $1 for amounts) is a warning that must be resolved, not bypassed.

#### Integrations
- **EarlyCheck (`fnma-earlycheck`, Direct Integration XML over the legacy DI platform; System-ID auth under the partner's TSP Product; integration environment for certification).** Request: the ULDD XML (MISMO 3.0) or DU Spec file (MISMO 3.4) with the partner's seller number; response: result data file with edit codes, severities, messages, DU Compare results, standardized address and computed fields. Idempotency: `(delivery_id, file_sha256, file_kind)` — an identical file is never re-submitted; a changed file is a new run. Acks/rejects: transport-level rejects are retried with backoff (3 attempts, 2/8/30 minutes); a schema rejection is a build failure routed back to `assembling`. Outage: after 60 minutes without a result, open a `fnma_portal_operator` task to run the same file through the EarlyCheck web UI and attach the UI export as `result_document_id` (`channel = ui`); the hash rule still applies. Version pinning: EarlyCheck release notes (2023–2026) are monitored; edits added in a release are mirrored into the Business Rules Dictionary snapshot.
- **Loan Delivery Test Environment (LDTE).** Optional schema/edit validation of the frozen file before hand-off ("ULDD Phase 5 edits are fatal in LDTE"); UI-only — used by the `fnma_portal_operator` during onboarding and after each ULDD revision, not per loan.
- **UCD Collection Solution, UCDP, DU** — no calls from 29.3; it reads 25.2/24.2/23.1 records. A missing identifier is an escalation to the owning process, never a re-submission from 29.3.
- **Fannie Mae Connect** — EarlyCheck Edit Messages file (reference data refresh, monthly).
- **Internal** — 29.4 receives `delivery_packages` (frozen); 27.1 supplies bailee-letter and payee context; 30.2 boarding reads `identifier_snapshot` (Fannie Mae loan number arrives later from 29.4).

#### Outputs and artifacts
- Frozen ULDD XML (`documents`, retention `fnma_loan_file_life_plus_4y`; Fannie Mae-confidential; not borrower-deliverable), EarlyCheck request/result files per run, DU Spec file used for the DU-file run, LDTE reports (onboarding), `uldd_data_points` (full provenance per Sort ID), `sfc_assignments`, `delivery_edits`, `delivery_packages` manifest with gate results and hash.
- Notices: none (no consumer artifact). Ledger: none (27.2 posts at purchase). Investor/delivery data: the package itself.
- Reports: daily "ready-to-deliver" queue (loans frozen, awaiting operator), EarlyCheck edit-frequency report (top edit codes by owner process — feeds 31.2 governance and 28.1 prefunding QC), SFC frequency report (compensatory-fee exposure), identifier-mismatch report.

#### AI agent design (AI-first)

`secondary` agent (package `agents/secondary`; 29.3 tools: `collectPrerequisites`, `assembleUlddDataPoints`, `evaluateConditionality`, `assignSfcs`, `reconcileIdentifiers`, `buildUlddXml`, `validateSchema`, `runEarlyCheck`, `mapEditToOwner`, `applyDerivedFix`, `freezePackage`, `writeDecision`). End-to-end: on `loan.funded` it collects every prerequisite record, evaluates each Appendix D conditionality, assembles and validates the file, runs EarlyCheck, resolves derivable edits itself (enumeration defaults such as SID 429, address normalization accepted from EarlyCheck's standardized output, format trims), routes non-derivable edits to the owning process with a `condition.reopened` (23.3) or a data-correction request (24.x/25.2/26.x), re-runs until clean, freezes and hashes, and hands off to 29.4. Decision record (`agent_decisions`): `{delivery_id, build_no, prerequisite_checks[], conditionality_decisions[{sort_id, condition, result}], sfc_set{code, rule_ref}, identifier_snapshot, earlycheck{run_id, severities, resolutions[]}, gate_results, uldd_sha256, rule_set_versions{uldd, sfc, du, ucd, uad, selling}, model_version, prompt_version, rationale, confidence}`. Guardrails: the agent never types a value that is not traceable to a source record (every `override_value` requires a rule reference and is limited to enumeration defaults and formatting — never amounts, dates, scores, values, identifiers); never bypasses a fatal or warning-to-fatal edit; never drops an SFC to fit the cap; never rebuilds after submission; never submits to Loan Delivery (29.4); never alters the DU casefile, UCD, UCDP or MI records — it asks their owners. Escalations: `fnma_portal_operator` (EarlyCheck UI fallback; LDTE checks), `officer` (partner) for an SFC set > 10, for any TPO-code question (211/212), and for a compensatory-fee-risk pattern (three or more loans in a month with a late-added SFC); `qc_officer` sees the EarlyCheck edit-frequency report monthly. Borrower-facing: none. Human path (`origination.ai_delivery_build = off`): the ops console exposes the same assembly, edit list and freeze button; the hash and gate rules are unchanged.

#### Edge cases and failure modes
- **Post-funding corrected CD (25.2 30-day window) before submission** → `delivery.package.superseded`; 25.2 must produce a new accepted UCD (`SM_O62_UCD_RESUBMIT_ON_CORRECTION`); rebuild on `ucd.accepted{is_final}`.
- **Appraisal Doc File ID belongs to another lender's submission** (broker-ordered appraisal re-used) → UCDP will not accept re-use; 24.2 must submit under the partner's registration; the gate blocks until a partner-owned Doc File ID exists.
- **Value acceptance offer older than four months at the note date** → SFC 801 is not permitted; 24.1 must have ordered an appraisal; if it did not, delivery is blocked and the loan goes to 23.3 `decision.reopened` (eligibility).
- **VantageScore 4.0 on one borrower, Classic FICO on the other** → LL-2026-06 violation; the build refuses; 22.2 re-pulls under one model and 23.1 resubmits (credit expiration and lock consequences handled there).
- **DU final submission hash differs from the closed-loan snapshot** (e.g., a payoff figure changed at closing) → 23.1 `final_closed_loan_match` resubmission; if the recommendation changes adversely, the loan is not deliverable until 23.3 resolves it.
- **UCD v1.5 vs v2.0** → 25.2 controls the version; 29.3 only asserts `status` and the casefile equality; the UCD "critical edits" are 25.2's.
- **eNote registered but Transfer of Control not yet possible** (SM as Secured Party) → the ULDD still carries `enote_indicator = true` and SFC 508; the transfer itself is 29.4's step.
- **Escrow waived** → SID 363 blank; no SFC (none found in the 09.09.2026 list); the LLPA matrix showed no escrow-waiver adjustment (00a-fnma §5.1 — re-verify before pricing).
- **Temporary buydown** → SFC 009 or 014 by the 2-point/2-year test; SID 145 Buydown Contributor Type populated; buydown funds sit in SM's T&I custodial account (SVC-2026-02; 30.3) — not delivered to Fannie Mae.
- **Texas 50(a)(6) / inter vivos trust / attorney opinion letter** → SFC 304 / 168 / 155 from 24.4; the trust borrower's note signature block (E-2-01 "Notes signed by trustee") is a custodial matter for 29.4.
- **EarlyCheck DI outage on the delivery day** → UI fallback by `fnma_portal_operator` with the identical file; the hash rule prevents a different file from being certified as "clean".
- **More than ten SFCs** → `officer` escalation; document the Fannie Mae instruction received before freezing.
- **Commitment expired or changed after freeze** → `delivery.package.superseded` on `commitment.modified` / `commitment.extended` / `commitment.expired` (29.1's events); rebuild with the new commitment number; 29.1 handles pair-off/extension economics.
- **Loan rescinded within the extended right (25.3) or repurchased by the warehouse (27.1)** before submission → `withdrawn`; package retained for audit.

#### Audit and evidence
- For Fannie Mae QC/MORA and LQC data-validation requests: the frozen ULDD file and its SHA-256, the per-Sort-ID provenance (`uldd_data_points` with source record and version), every EarlyCheck request/result pair with severities and resolutions, the gate results at freeze, the SFC rule references, and the identifier snapshot with the DU findings, UCD feedback and UCDP SSR document ids.
- For the partner: the decision record per build, the edit-frequency and SFC reports, the compensatory-fee exposure log, and proof that no fatal edit was bypassed.
- For CFPB/state exams and litigation: the ULDD is investor data, not a consumer disclosure — evidence needed is the tie-out between the delivered figures and the CD/note (`cd_consistency_checks`, 25.2) which the "C" edits mirror.
- LL-2026-04: every build is an `agent_decisions` row with rule-set, model and prompt versions; edits resolved by the agent are enumerated with the rule applied.

### Open questions / decisions
1. **Property Data ID, Income Calculator identifier and DU validation report identifiers in ULDD.** Not found as Phase 5 data points on the pages read. *Default:* persist them in `identifier_snapshot` and assert presence; do not write them into the ULDD unless Appendix D (to be loaded from the Excel specification) shows a Sort ID; re-check the Phase 5 (5.2.0) Appendix D during rule-set load.
2. **SID 398.3 for whole loans.** Fannie Mae's guide describes the Wire Instruction Reference Identifier as MBS-only. *Default:* leave blank for whole-loan cash deliveries; wire designation by payee code (Form 482) and, under a bailee letter, SID 642/650.1; confirm with the Fannie Mae Integration Team whether a whole-loan wire nickname import exists (Loan Delivery FAQ Q31–Q32 speak only of "conditionally optional").
3. **TPO codes (211/212) for SM's fulfillment role.** A3-3-01's TPO definition could capture SM (00a-fnma §8). *Default:* no SFC 211/212 (SM is neither correspondent nor broker; the partner is the originator of record) — the partner's counsel confirms with its Fannie Mae account team before the first delivery; the SFC rule is a feature flag `delivery.sfc_tpo_code` ∈ {none, 211, 212}.
4. **SFC 873 / FTHB ≤ 100% AMI LLPA waiver.** Not found in the 09.09.2026 list extraction. *Default:* treat the waiver as derived by Loan Delivery from FTHB and income data; re-read the PDF; if a code exists, add it to 20.4/23.2's set.
5. **EarlyCheck DU-file run reuse.** *Default:* the pre-closing run on the final DU Spec file (23.1) is reused when the file hash is unchanged; otherwise re-run; the ULDD run is always fresh per build.
6. **Warning-edit bypass policy.** *Default:* warnings require a recorded justification tied to a rule; warning-to-fatal edits are treated as fatal from the day Fannie Mae announces the effective date in the release notes (rule-set flag per edit code).
