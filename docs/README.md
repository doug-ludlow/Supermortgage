# The documentation

What each file under `docs/` is for, and which are current. The specification itself lives under [`spec/`](../spec/); this folder holds what is written *about* the build.

| Document | What it is | Status |
|---|---|---|
| [ARCHITECTURE.md](ARCHITECTURE.md) | The conventions that are not optional (bigint cents, the six calendars, append-only records, balanced ledger sets, registry-driven timers), the shape of a process, how a section is added, and the one-product seam between servicing, origination, the borrower surfaces and the operations runtime. | Current (rewritten 2026-09-16). |
| [DEPLOY.md](DEPLOY.md) | The owner's runbook for the Google Cloud nonprod environment: the bootstrap script, the GitHub variables, the deploy workflow, DNS, the demo portfolio, the demo clock, the daily refinance check, the FAKE reviewers, the borrower API, what is and is not real in nonprod, the path to production, troubleshooting. | Current (audited 2026-09-16). |
| [du-graph.md](du-graph.md) | Why a DU submission is a relationship graph, the arcs the database must answer, and how the generated tables are re-verified on every test run (`npm run du:verify`). | Current. |
| [AUDIT-NOTES.md](AUDIT-NOTES.md) | Discrepancies between the spec's prose figures and what the engines compute, found while porting the worked examples of sections 1–19. Superseded as a verification record by `audit/VERIFICATION.md`; kept because each row explains a test comment that still exists. | Historical. |
| [audit/COVERAGE.md](audit/COVERAGE.md) | The measured status: every process's units built over units specified, regenerated by `npm run audit`. The only allowed statement of progress. | Regenerated on every run. |
| [audit/baseline.json](audit/baseline.json) | The ratchet: totals that may never fall (`tools/audit.py --check`, run by `npm test`). Moved up by `npm run audit:baseline` in the same commit as the work that earned it. | Live. |
| [audit/VERIFICATION.md](audit/VERIFICATION.md), [audit/verification-amendments.json](audit/verification-amendments.json) | The 2026-09-15 verification of every cited rule, deadline, threshold and worked figure against primary sources, and the 324 amendments it produced (each a spec change paired with a test change; 1–270 for sections 1–31, 271–324 for section 35). | Current. |
| [audit/hosted.json](audit/hosted.json), [audit/persisted.json](audit/persisted.json) | The two execution columns 35.11 adds to the audit: tools executed over the hosted API by `tools/hosted-probe.ts`, and tables that hold rows after the journeys (`tools/persisted-count.ts`). | Regenerated by CI and the probe. |
| [audit/AUDIT-REPORT.md](audit/AUDIT-REPORT.md) | The end-of-build audit of 2026-09-10 against the then 114-process spec: the coverage layer and a hands-on reading of eight engines. Its findings were worked off (task "Cross-cutting defects"). | Historical. |
| [decisions/](decisions/) | Dated owner decisions, recorded verbatim. A decision that retires part of the spec is cited by the matching row of `spec/registry/retired.json`, which the audit subtracts before it counts. | Append-only. |
| [ux/](ux/) | The borrower experience design: chapters 00–18 (the master index, foundations, data contracts, the journeys, the copy library in `12-message-copy-library.md`, the acceptance tests, entry and sign-in, the conversational product, the Apply product in `18-the-apply-product.md`) and `BACKEND-DELTAS.md`, the ledger of what the UI needed the backend to add. `tools/import_ux.py` (`npm run spec:import:ux`) turns these chapters into section 32 of the spec. | Current; the chapters are the source the spec is generated from. |
| [partner-portal/](partner-portal/) | The build brief and backend deltas for section 36, the servicing partner portal. Section 36 is specified and scaffolded; nothing is built yet. | Current for a section not yet started. |
| [console/](console/) | Screenshots of the operator console. | Illustrative; the screens have moved on since (see section 34 and 35.8). |

Two rules for anyone editing here: a number in prose is a claim, so quote it from `audit/COVERAGE.md` or the code rather than from memory; and a process is never "done" in these pages, only at 100% of its units in the coverage table.
