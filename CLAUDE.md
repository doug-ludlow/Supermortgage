# Supermortgage — working notes for Claude

- The spec under `spec/` is the source of truth. Before touching a process, read its markdown end to end; reproduce its T-numbered acceptance tests verbatim as `node:test` cases and its worked arithmetic as assertions.
- Conventions are listed in `docs/ARCHITECTURE.md` and are not optional: bigint cents, PlainDate + the four named calendars, append-only event/ledger/decision tables, balanced ledger sets with `rule_ref`, registry-driven timers, officer-only waivers on money fields.
- Node 22 type-stripping runs `.ts` directly: erasable syntax only (no `enum`, no parameter properties, no namespaces). `npm test` and `npm run typecheck` must both pass before a commit.
- Timer rows that the offset grammar can't parse are listed by `npm run spec:lint -- --verbose`. Handle them with a cited override in the section's `timers.ts`, never by hard-coding a deadline in service code.
- Postgres: `service postgresql start`, then `DATABASE_URL=postgresql://sm:sm@localhost/supermortgage db/migrate.sh`. Migrations are append-only too — new file, never edit an applied one.
- Status is measured, not remembered. The only allowed statement of progress is a fraction from `npm run audit` (it reads `spec/registry/manifest.json`, the spec in its own units: T-ids, tables, timers, notices, tools, worked figures; a T-id counts only as a non-todo `node:test` titled exactly `<pid>-T<n>: <spec text>`, a timer only when armable, satisfiable and its events emitted by source — `--lenient` shows the older, looser count). Never a check mark, never "done"/"complete" in prose. A process is done only when its row in `docs/audit/COVERAGE.md` is at 100% of its units; every completion claim quotes that row or the totals line verbatim.
- Origination (sections 20–31) and servicing (1–19) are one product with one id grammar: `tools/import_origination.py` brought the Origination build specification in as 20–31 (O2.3 → 21.3); a name means one thing on both sides. `python3 tools/spec_lint_names.py` (run by `npm test`) fails on a timer code re-triggered by a different event in a later section, an agent/role/calendar the kernel lacks; the registry lets the lowest-numbered section own a shared code. Markdown-first sections' timer rows are re-derived from the file by `npm run spec:register` (rename a code in the table and re-run).
- Section 32 is the borrower experience, imported by `tools/import_ux.py` (`npm run spec:import:ux`) from `docs/ux/` — it projects sections 1–31 and owns no timer, notice or worked figure; its tests are API-level `node:test` plus Playwright driven from `node:test` in `src/domain/borrower`; every vendor (Stripe Identity, Plaid, Truv, IRS IVES, carrier connection, RON, DU, EarlyCheck, telephony/SMS/e-mail, print/mail) is an in-repo fake named `FAKE` in every build stage.
- New spec sections are markdown-first: copy `spec/TEMPLATE-process.md` (and `spec/TEMPLATE-section-README.md`) into `spec/sections/NN-slug/`, keep its headings verbatim, then `npm run spec:register && npm run spec:manifest && npm run spec:scaffold` so the audit measures the new section from its first commit. The template's comment block states the exact textual form of each counted unit.
- Plan in spec units too: a task is "2.5: T4, T7 verbatim; 2 timers satisfiable; NTC_… authored; 6 tools on the bus", never "finish cashiering". The per-process files `src/domain/<section>/<n>-<m>.spec.test.ts` (`npm run spec:scaffold`, never overwrites) hold one `node:test` per T-id named exactly as the spec; implement a T-id by replacing its `todo: true` line with the real test. Todo tests are not counted.
- Ratchet: `npm test` ends with `tools/audit.py --check`, which fails if any total in `docs/audit/baseline.json` falls or a process listed there as done drops below 100%. Move the baseline up with `npm run audit:baseline` in the same commit as the work that earned it; never move it down.
- Hooks in `.claude/settings.json` run the audit on SessionStart, on every prompt and on Stop, so the current fractions are always in context. If the ratchet line says FAILED, fix that before anything else.
